# Faultline: как показать проект на собеседовании

Это лаборатория сбоев распределённой системы на C++20. Она находит устаревшее чтение, сокращает сценарий и объясняет события на временной шкале.

```sh
make test
./build/faultline search 0 1000 1 build/failure
# Код возврата 1 ожидаем: найдено нарушение.
cat build/failure.fl
./build/faultline replay build/failure.fl 1 build/failure.json
./build/faultline replay build/failure.fl 2 build/safe.json
```

Откройте `web/index.html` в браузере. Переключайте R=1/R=2, двигайте ползунок или загрузите JSON собственного прогона.

Что стоит уметь объяснить:

- Почему успешная запись в две реплики не гарантирует свежесть чтения из одной.
- Почему R+W>N обеспечивает пересечение кворумов и какие предпосылки нужны.
- Зачем планировщику второй ключ сортировки для событий с одинаковым временем.
- Чем минимальный по удалению сценарий отличается от самого короткого.
- Почему 2000 успешных случайных прогонов не являются математическим доказательством.
- Почему проверяемое свойство слабее линеаризуемости и зачем атомарному регистру может понадобиться write-back.

В README и архитектуре честно указаны ограничения: фиксированные задержки, отсутствие реальной сети, диска, консенсуса и восстановления данных. Проект создан с помощью Codex; используйте его как основу для собственных экспериментов. Убедительнее всего будет добавить своё расширение, воспроизвести новый сбой и защитить принятое решение.
